# CI/CD

```
 воскресенье 01:23 UTC                     ежедневно 03:17 UTC                     сервер, каждые 6 ч
┌──────────────────────┐   workflow_call   ┌──────────────────────────┐  raw    ┌─────────────────────────┐
│ refresh-ripe-data    │ ────────────────▶ │ update-blacklists        │ ──────▶ │ ru-blacklist-update     │
│ RIPEstat + дампы RIPE│                   │ сборка → проверки → push │  GitHub │ (systemd timer, pull)   │
│ → auto/*.txt         │                   │ → blacklists*/           │         │ → nftables / ipset      │
└──────────────────────┘                   └──────────────────────────┘         └─────────────────────────┘
                     ci.yml: каждый push и PR — линтеры, тесты, загрузка файлов в nft/ipset, e2e деплоя
```

## Workflow'ы

| Файл | Когда | Что делает |
|---|---|---|
| `ci.yml` | каждый push в `main`, каждый PR, вручную | ruff, pytest (Python 3.10 и 3.13), shellcheck, actionlint. Перегенерирует nft/ipset/nginx/routes из закоммиченных списков, загружает их в nftables и ipset в отдельном network namespace и прогоняет серверный скрипт деплоя end-to-end (оба бэкенда). |
| `update-blacklists.yml` | ежедневно в 03:17 UTC (10:17 по UTC+7), вручную, после `refresh-ripe-data` | Собирает списки (RIPEstat + whois), проверяет их так же, как `ci.yml`, сравнивает с опубликованной версией и коммитит изменения в `main`. |
| `refresh-ripe-data.yml` | по воскресеньям в 01:23 UTC, вручную | Скачивает список RU-ресурсов из RIPEstat и дампы RIPE DB (`aut-num`, `inetnum`, `inet6num`, `organisation`), офлайн резолвит имена ASN и сетей, обновляет `auto/`, затем запускает `update-blacklists`. |
| `dependabot.yml` | еженедельно | Открывает PR с обновлениями Python-пакетов и GitHub Actions. CI проверяет каждый такой PR. |

Что изменилось по сравнению с апстримом:

- **Свой репозиторий вместо чужого.** Пуш идёт встроенным `GITHUB_TOKEN` (`permissions: contents: write`), секрет `GH_PAT` не нужен. Старые workflow'ы пушили в `C24Be/AS_Network_List`.
- **Описания резолвятся из дампов RIPE DB.** Раньше было ~19 тыс. whois-запросов в месяц, которые упирались в лимиты RIPE (у 3790 из 5750 ASN не было описаний, в том числе у AS61280 ГРЧЦ). Теперь используется 4 скачивания в неделю; whois остаётся только как запасной вариант (не больше 300 запросов, всегда с флагом `-r`).
- **Нет коммитов «на пустом месте».** Коммит появляется только если изменилось содержимое; строки `# Last updated` / `# Generated` при сравнении игнорируются.
- **Сбой сборки не публикует частичный список.** Любая ошибка RIPEstat или whois прерывает сборку до записи файлов.

## Защита от плохих данных

1. **При сборке.** Если whois или RIPEstat ответили ошибкой, job падает, а опубликованные файлы остаются прежними.
2. **Shrink guard.** `diff_blacklists.py` сравнивает новый `blacklist.txt` и `blacklist-vk.txt` с версией в `main` по **покрытому адресному пространству**, а не по числу строк. Если пропало больше 25% IPv4- или IPv6-покрытия, публикация отменяется. Отчёт с таблицей и списком добавленных/удалённых сетей попадает в Summary запуска.
3. **Проверка загрузки.** Перед коммитом все `.nft` и `.ipset` реально загружаются (по два раза) в изолированный network namespace, а серверный скрипт применяется с обоими бэкендами.
4. **На сервере.** `ru-blacklist-update` не применяет список с мусором, со слишком малым числом записей или резко уменьшившийся. В этих случаях он оставляет текущие правила (подробнее в [`deploy/README.md`](../deploy/README.md)).

Если уменьшение ожидаемое (например, вы удалили паттерн), запустите
**Actions → Update blacklists → Run workflow** с галочкой *skip_guard*.

## Что сделать один раз после мержа

1. Откройте **Actions** и убедитесь, что workflow'ы включены.
2. Запустите **Refresh RIPE data → Run workflow**. Первый запуск занимает 10–20 минут: заполнятся описания в `auto/`, затем пересоберутся все списки. Учтите, что в список попадут ASN, которые раньше выпадали из-за неразрезолвленных описаний (например, AS61280).
3. Если в **Settings → Secrets → Actions** остался секрет `GH_PAT`, его можно удалить.
4. Если включите защиту ветки `main` (branch protection / rulesets), разрешите пуш для `github-actions[bot]`, иначе ежедневные коммиты перестанут проходить.

Уведомления: письма о сбоях запусков по расписанию GitHub отправляет тому, кто последним менял `cron` в файле
workflow, то есть вам после мержа. Настраиваются в **Settings → Notifications → Actions**.
В публичных репозиториях GitHub отключает расписания после 60 дней без активности в репозитории и
предупреждает об этом письмом; включить их обратно можно на вкладке Actions.

## Как менять списки

- **Паттерны имён:** `lists/black-names.txt`, `lists/white-names.txt`, `lists/vk-names.txt` (одно регулярное выражение на строку, есть комментарии и закомментированные предложения).
- **Свои адреса и ASN:** `lists/custom-blacklist.txt` (основной список: на сервере блокирует **входящие** соединения
  из этих сетей) и `lists/custom-vk.txt` (VK-список: блокирует **исходящий** трафик VPN-клиентов и сервера к этим сетям).
  Одна запись на строку: `AS12345` (все префиксы, которые ASN анонсирует, обновляются ежедневно) или `203.0.113.0/24`.
- **Ложные срабатывания:** добавьте префикс в `lists/allowlist.txt`, и он будет вырезан из всех списков.
- **Гос. netname'ы:** `lists/ru-gov-netnames.txt`.

Опечатку (не ASN и не префикс, битая регулярка) CI покажет сразу после push. Изменения попадут в списки
при следующем ежедневном запуске; чтобы применить сразу, запустите **Update blacklists** вручную.

## Локально

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt
pytest
ruff check .
shellcheck -x ./*.sh ./*.subr deploy/*.sh tests/integration/*.sh
actionlint
sudo tests/integration/test_deploy.sh     # нужны nft, ipset, iptables; хост не затрагивается
```
